# 控制台后台（BFF）

**BFF** = **Backend for Frontend**（面向前端的后端）：专门为 Nebula 控制台网页提供 API 的服务（进程 `nebula-bff`，默认端口 `18090`）。

你在浏览器里点的按钮、填的表单，大多由 BFF 处理：它写「要部署哪个模型、几个副本」，读「当前有哪些机器、GPU、告警数据」，**不替代**用户推理时走的那条网关 → 路由器 → 引擎主路径。

---

## 控制台功能对应关系

| 你在页面上… | 后台在管… |
|-------------|-----------|
| 登录、改密码 | 用户与会话（存在 PostgreSQL） |
| 模型服务：部署 / 停止 / 扩容 | 模型部署期望，交给调度器去执行 |
| 模型目录 / 模型库 | 下载任务、已下载文件、存储路径 |
| Serving Cell | 登记外部推理集群入口 |
| 治理 | 兼容规则、硬件清单、SLO、试用版本、租户与费用 |
| 网关观测 / 推理 / 审计 | 从观测系统汇总数据展示 |

```
浏览器 → BFF → 配置库（etcd）→ 调度器 / 节点 真正起停模型
            → 数据库（用户与设置）
            → 观测系统（图表与审计）
```

---

## 和网关的分工

- **用户调 API 问模型问题** → 走 **Gateway**，不经过 BFF。  
- **你在控制台点「部署模型」** → 走 **BFF**，不经过 Gateway 推理路径。  

这样管理操作和推理流量分开，互不影响。

---

## 观测与审计相关配置

BFF 读 xtrace 给控制台展示图表和审计。两种常见模式：

| 模式 | 何时用 |
|------|--------|
| `OBSERVE_AUTH_MODE=internal` | 内网开发/测试，可不配观测令牌 |
| `OBSERVE_AUTH_MODE=service` | 生产环境，必须配 `OBSERVE_TOKEN` |

若审计页报 Unauthorized，多半是观测令牌未配或与 xtrace 不一致。检查步骤见 [`deployment.md`](./deployment.md) 第 5 节。

## 实施说明

控制台 API 前缀一般为 `/api/v2/...`。新功能只加在这一层；网关上的旧管理接口逐步只保留只读能力。字段细节以当前版本代码为准。
