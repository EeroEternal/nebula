# 网关与路由器

对外 API 的「大门」和「分诊台」：先验身份、记日志，再把请求分到合适的模型实例上。

---

## 用一句话区分

| 组件 | 通俗说法 | 主要工作 |
|------|----------|----------|
| **Gateway（网关）** | 大门保安 + 前台 | 校验访问令牌、限流、记审计；支持多种 API 格式；**不决定**进哪台机器 |
| **Router（路由器）** | 分诊台 | 看哪台模型实例最空闲，把请求转过去；失败时重试、暂时屏蔽坏实例 |

```
调用方 → 网关 → 路由器 → 某台 GPU 上的推理程序
              ↘ 控制台后台（管模型，不走推理主路）
```

---

## 网关里有哪些能力

| 能力 | 说明 |
|------|------|
| 登录与权限 | 配置访问令牌；可绑定租户；可限制每分钟请求次数 |
| 操作记录 | 重要调用与管理操作写入审计系统 |
| 协议转换 | 兼容 OpenAI、Anthropic 等常见调用格式 |
| 监控数据 | 同时供控制台和公司 Prometheus 使用 |

---

## 路由器里有哪些能力

| 能力 | 说明 |
|------|------|
| 实例列表 | 自动同步当前有哪些模型副本在提供服务 |
| 选实例 | 默认优先分给排队最少的副本 |
| 自我保护 | 某副本连续出错会暂时不再分配流量；可自动换副本重试 |
| 监控数据 | 记录延迟、首 token 时间、错误类型等 |

---

## 日常运维要注意什么

**改配置或发版时建议顺序：** 先动路由器、观察约半小时，再动网关。

**怎么算改成功了：** 正常提问有回答；偶尔单台机器故障时，重试或熔断计数会上升，但整体错误率不应长期恶化；过大的请求会被拒绝（类似「文件太大」）。

**需要回滚时：** 可先关掉路由器自动重试做临时止血，或整体换回上一版程序并确认健康检查通过。

**和监控的关系：** 控制台「网关观测」页看的是汇总数据；详细指标说明见 [`observability.md`](./observability.md)，告警怎么处理见 [`slo.md`](./slo.md)。

## 实施参考：常用环境变量

以下供实施工程师在 `deploy/nebula.env` 或启动命令里配置。

**网关**

| 变量 | 含义 |
|------|------|
| `NEBULA_GATEWAY_ADDR` | 网关监听地址，默认 `8081` |
| `NEBULA_ROUTER_URL` | 路由器地址 |
| `NEBULA_AUTH_TOKENS` | 访问令牌，格式 `令牌:角色` 或 `令牌:角色:租户` |
| `NEBULA_AUTH_DISABLED` | 仅开发环境：关闭鉴权 |
| `NEBULA_MULTI_TENANT` | 开启后按租户配额限流 |
| `NEBULA_AUTH_RATE_LIMIT_PER_MINUTE` | 每令牌或租户每分钟请求上限 |
| `NEBULA_LOG_FORMAT=json` | 建议生产环境开启，便于收集日志 |

**路由器**

| 变量 | 含义 |
|------|------|
| `NEBULA_ROUTER_RETRY_MAX` | 失败时最多换几个副本重试 |
| `NEBULA_ROUTER_RETRY_BACKOFF_MS` | 重试间隔（毫秒） |
| `NEBULA_ROUTE_CIRCUIT_FAILURE_THRESHOLD` | 连续失败多少次后暂时屏蔽该副本 |
| `NEBULA_ROUTE_CIRCUIT_OPEN_MS` | 屏蔽多久后再尝试 |

完整列表与默认值见 [`deployment.md`](./deployment.md) 与仓库 `deploy/nebula.env.example`。
