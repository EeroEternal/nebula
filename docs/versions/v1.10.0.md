# Nebula v1.10.0

发布日期：2026-09-22。

完整变更见根目录 [`CHANGELOG.md`](../../CHANGELOG.md)。

## 一句话

**功能版**：数据面拿到「**有界公平准入**」（P0-#2，引擎侧 P99 −74%）与「**单模型多副本**」；控制面完成「**多引擎对齐**」（vLLM / SGLang 同一套能力、指标、健康）；并把 `replica_specs` 的 **GPU 与节点放置** 真正打通。

## 主要变化

| 模块 | 变更说明 |
|------|----------|
| **有界公平队列（P0-#2）** | Gateway 在触达引擎前走 per-model 有界队列：并发上限 + 每租户份额 + `fair`/`fast_fail` + 超限 **429**；guard 覆盖流式全程；TTFT 拆成 `x-nebula-queue-wait-ms` 与 `x-nebula-upstream-ttft-ms`。真机：C=64 时引擎侧 P99 TTFT **311 ms → 82 ms（−74%）**。代码：`crates/nebula-common/src/queue.rs`。 |
| **单模型多副本** | `ModelDeployment.replicas` 起 N 个引擎 Pod（replica 0 = `nebula-{model}`，其余 `nebula-{model}-{n}`），各绑不同 GPU，各写 `/endpoints/{model}/{replica}` 与 `/stats/{model}/{replica}`。真机：2 副本 `LeastPending` 132/128（≈50/50），前缀缓存命中 0.92/0.93。 |
| **多引擎对齐（vLLM / SGLang）** | 指标解析下沉 `nebula_common::engine_metrics`，由 `parse_engine_metrics(engine_type, …)` 分派；node 与 k8s-controller 共用。k8s-controller 按 `ModelSpec.engine_type` 选镜像/启动参数。真机：SGLang Pod endpoint `engine_type: "sglang"`、`/stats` 走 SGLang 解析器、端到端 chat 正常。详见 [`../dev/engines.md`](../dev/engines.md)。 |
| **replica_specs 放置** | `replica_specs[i].gpu_indices` 与 `node_id` 都生效：副本绑指定 GPU；指向他节点的副本由本节点 agent **跳过**（不再重复建 Pod）。真机验证 `[1, 3]` → GPU 1 / GPU 3。 |
| **嵌入式 Router（opt-in）** | `NEBULA_ROUTER_MODE=embedded` 进程内选路（含 `/v1/responses`、`/v1/messages`、重试对等、router 指标）。实测 P99 **中性**（跳是 loopback），默认仍为 `remote`。 |
| **阶段埋点（opt-in）** | `NEBULA_GATEWAY_STAGE_TIMING=1` 打印逐请求 `recv → body → prep → upstream_hdr → first_chunk`。结论：Gateway 自身开销 ≈ 0。 |
| **运维脚本** | `scripts/nebula-stack.sh`（start/stop/status）、`scripts/verify-embedded-router.sh`。 |
| **文档** | `docs/dev/hw/vllm-serving-perf.md`、`landscape.md`、`direction.md`、`queue-admission.md`、`prefix-affinity.md`、`engines.md`。 |

## 修复

- **指标子串误匹配**：`extract_metric` 曾把 `external_prefix_cache_*` 计入 `prefix_cache_*`，污染命中率；改为全名匹配。
- **SGLang 不可达**：SGLang 默认绑 `127.0.0.1`（vLLM 是 `0.0.0.0`）→ 补 `--host 0.0.0.0`；`/metrics` 需 `--enable-metrics`。
- **SGLang endpoint 反复过期**：`/health` 响应 >800 ms，就绪探测超时 → endpoint 靠 TTL 过期；探测超时提到 3 s。
- **缩容/恢复**：缩容删多余副本；Pod 处于终止态时重建；非 `Running` 时清 stale endpoint。
- **`nebula-stack stop`** 漏删非 replica-0 的 Pod（现按 `nebula.model_uid` 标签全删）。

## 升级注意

- **无破坏性变更**，`v1.9.2 → v1.10.0` 可直接覆盖升级。
- **新增能力默认关闭或向后兼容**：有界队列需显式 `NEBULA_GATEWAY_QUEUE_ENABLED=1`；嵌入式 Router 需 `NEBULA_ROUTER_MODE=embedded`；阶段埋点需 `NEBULA_GATEWAY_STAGE_TIMING=1`。未设置时行为与 v1.9.2 一致。
- **行为变化点**：启用有界队列后，超出并发/等待上限的请求会被 **429** 拒绝（此前为无界排队）；多副本模式下，同一模型会出现 `nebula-{model}-{n}` 命名的额外 Pod。
