# Nebula v1.11.0

发布日期：2026-11-19。

完整变更见根目录 [`CHANGELOG.md`](../../CHANGELOG.md)。

## 一句话

**高可用与多引擎深化版**：补齐 **Gateway 活成员配额自动分片** 与 **热路径全内存快照**（消除逐请求 etcd 读）、新增 **TokenSpeed / zstep（含在线 APC 与 `dspark`/`mtp`/`ngram` 投机解码）** 运行时、落地 **KV 资源化治理（Batch 5/6）与前缀聚合路由**，并完成 **`UpstreamTransport` 统一出站契约** 与 **隔离 GPU Opt-in Autotune**。

## 主要变化

| 模块 | 变更说明 |
| :--- | :--- |
| **Gateway 高可用与热路径治理** | 1. 基于 `/gateways/{id}` etcd 租约实现集群配额动态分片与引擎队列容量联动，支持 `fail_closed`（默认 503）/`fail_open` 显式降级。<br>2. 新增 `GatewayMetaSnapshot` 响应式监听 `/tenants/` 与 `/models/`（含 `served_model_name` 别名与负缓存），彻底消除推理热路径逐请求 etcd `store.get`。<br>3. `ConcurrencyGuard` 改用 `Arc<AtomicU64>` 原子释放；`ToolPauseTracker` 补齐 `remote` 路由模式下的 Tool-Pause 队列优先级。 |
| **多引擎扩展（TokenSpeed & zstep）** | 1. 新增 `TokenSpeed` 一等引擎支持，并将动态 `block_size`、首包排空与三类注意力 KV 容量模型合入路由与容量估算。<br>2. 新增 `zstep` 运行时适配、在线 APC 契约以及 `dspark` / `mtp` / `ngram` 投机解码参数校验与指标解析（8× RTX 6000D 真机验证通过）。 |
| **KV 资源化与 `pd_split` v1** | 1. `pd_split` 完成全链路（Router 阶段过滤、LMCache `/lookup` 暖信号、节点/K8s 启动顺序门控、批准镜像白名单与故障注入演练）。<br>2. 落地 KV L1/L2 声明与超分告警、Tool-Pause 会话脊柱 L1 Pin 租约、`pin_budget_gb` 扣减及 `/cache/{lookup,pin,clear,warmup}` API。 |
| **前缀路由与流式可靠性** | 1. `PromptHasher` 支持 `chat_template` 预编译缓存、`bos_token` / `chat_template_kwargs` 对齐；`PrefixAffinity` 与会话亲和引入 Bounded-Load Rendezvous 聚合与软逃逸。<br>2. 流式响应强制实行分阶段超时（首包/空闲/跨重试预算）、首字节前副本重试，以及失败时发送 OpenAI 格式错误帧（永不伪造 `[DONE]`）。<br>3. 抽象单一出站契约 `UpstreamTransport`（`reqwest` 默认 / 可选 `xlite`）。 |
| **治理、压测与工程重构** | 1. 压测 v2 支持有界闭环并发、开环到达、客户端 TTFT/TPOT 与 SLO Goodput 归档；Roofline 选型要求绑定作用域的原生精度声明。<br>2. Opt-in 隔离 GPU 自动调优（`bin/nebula-autotune`）上线。<br>3. `nebula-k8s-controller` `kubectl` 全面异步化；`nebula-router/src/lib.rs` 拆分为 `sse` / `pd_split` / `tool_pause`；补齐 `nebula-meta` 与前端 `i18n` AST 校验门禁。 |

## 升级注意

- **无破坏性持久化变更**，控制面与 PostgreSQL 表结构向后兼容。
- **行为与配置提示**：
  - `replicated` 拓扑下显式声明 `kv_sharing` 现会在校验阶段被拒绝（此前静默忽略）。
  - Gateway 热路径在初始快照完成同步后，缺失的租户/模型不再穿透查询 etcd；冷启动窗口失败时遵循 `NEBULA_GATEWAY_QUOTA_DEGRADED`（默认 `fail_closed` 返回 `503`）。
  - `pd_split` 需通过 `NEBULA_APPROVED_PD_IMAGES` 配置允许的镜像，且需先启动 `lmcache_controller` 再启动引擎。
